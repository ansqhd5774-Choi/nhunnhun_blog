# GitHub Actions 최소 실행 정책

## 적용 범위

`nhunnhun_blog`는 공개 저장소다. 콘텐츠 CI, 작성 회귀 검사, 스킨 소스 검사, 신규 글 사전 검증, 준비된 원고 전달은 표준 GitHub 제공 `windows-latest`에서 실행한다. 실제 발행·수정과 PC 유지보수는 전용 셀프 호스티드 `tistory-publisher`에서 실행한다. PC 작업을 GitHub 제공 러너로 대체하지 않는다.

- 공통 코드 검사는 콘텐츠 CI에서 실행하며 발행 경로의 전체 테스트 중복을 제거했다.
- 원고와 스킨 변경은 관련 경로에 대해서만 검사를 실행한다.
- 작성 회귀 검사의 취소 그룹은 PR별로 분리했다.
- 기존 글 수정은 명시적인 dispatch만 허용하며 발행 직전 대상 원고 검증은 유지한다.
- Chrome 자동 시작 제거 같은 유지보수는 수동 dispatch로만 실행한다.
- 회귀 검사는 검증·전달의 표준 제공 러너 사용과 PC 작업의 전용 셀프 호스티드 러너 사용을 확인한다.

## 효과 산정

공개 저장소의 표준 제공 러너 실행은 비공개 저장소용 포함 분을 소비하지 않는다. 기존 셀프 호스티드도 포함 분을 소비하지 않았으므로 이 전환의 직접 과금 분 절감은 **0분**이다. 검증·전달은 PC 작업과 러너 대기열을 공유하지 않게 된다. 실제 속도 향상 비율은 전후 같은 작업을 비교하기 전 확정하지 않는다. 과거 제공 러너 소비 887분은 현재의 일일 소비량으로 사용하지 않는다.

기존 실행시간 표본의 PR 검사 153초→72초, push 검사 98초→62초를 합친 251초→134초는 특정 제거 대상에 대한 초기 추정이다. 46.6%를 계정 전체 과금 절감률로 사용하지 않는다. 최종 변경 후 전후 실측 비교는 미완료다.

유지보수 push 트리거 제거는 해당 YAML 변경이 main에 반영될 때 자동 작업 1회를 없앤다. 변경 빈도와 실제 실행시간 자료가 없으므로 월 절감 분은 산출하지 않는다.

579분의 잔량과 2,421분 누적치는 사용자 제공 스냅샷이다. 계정 전체 잔량 유지 기간을 산출하려면 다른 저장소를 포함한 실제 제공 러너의 일일 소비량과 해당 작업의 적용된 절감량이 필요하다. 이 저장소 변경으로 유지 기간이 늘어난다고 보고하지 않는다.
