# Editorial R4 — 의미 중심 강조·문체·공개 검증

**ACTIVE: `contentStandard="R1"`인 새 글·앞으로 수정하는 글.** 변경 없는 기존 source는 R3 renderer와 이전 해시를 유지한다. R4는 스킨·광고·사이트 카테고리를 변경하지 않는다. 2026-10-07.

## 1. 역할을 먼저 정한다

| 표현 | 의미 | 주의 |
| --- | --- | --- |
| `<strong>` | 핵심 사실·조건·수치 | 문단 전체를 굵게 하지 않는다 |
| `<em>` | 짧은 보충·용어 설명 | 읽기 어려운 긴 기울임 문장 금지 |
| `<u>` | 짧은 비교·차이 | R4에서 실제 밑줄이며 형광펜으로 바꾸지 않는다 |
| `<mark data-tone="key">` | 기억할 핵심 | 짧은 단어·구절만 |
| `<mark data-tone="action">` | 근거 있는 실생활 행동 | 불확실한 효능을 확정 추천처럼 표시하지 않는다 |
| `<mark data-tone="info">` | 이해에 필요한 기준 | 단순 장식 금지 |
| `<mark data-tone="caution">` | 중요한 주의 | 내용 자체에도 주의 조건을 적는다 |
| `<mark data-tone="danger">` | 즉시 행동이 필요한 위험 | 위험 범위에 맞는 표현만 |
| `<span data-tone="...">` | 같은 의미 체계의 글자색 | 색만 보고 의미를 알아야 하는 구성 금지 |

형광펜 팔레트: key 배경 `#fff1a8`, action `#dcfce7`, info `#dbeafe`, caution `#ffedd5`, danger `#fee2e2`. 대응 전경색은 코드의 팔레트 상수에서 관리한다. 문장 순서에 따라 색을 돌리지 않는다. 같은 의미 강조 두 개가 같은 색이어도 정상이다. 과거 R3의 최소 2색 순환 검사는 R4에 적용하지 않는다.

## 2. 배지는 색이 아니라 글자로도 구분된다

```html
<blockquote data-kind="tip"><p>알아두면 선택에 도움이 되는 설명입니다.</p></blockquote>
<blockquote data-kind="check"><p>구매·자가 점검에서 확인할 사항입니다.</p></blockquote>
<blockquote data-kind="caution"><p>해당 조건에 해당하면 먼저 확인할 주의사항입니다.</p></blockquote>
<blockquote data-kind="danger"><p>위험 신호와 즉시 해야 할 행동을 설명합니다.</p></blockquote>
<blockquote data-kind="care"><p>어떤 상황에 의료진과 확인할지 설명합니다.</p></blockquote>
```

렌더러가 각각 `생활 팁 / 확인할 점 / 주의 / 즉시 확인할 위험 신호 / 진료·상담이 필요한 경우`의 눈에 보이는 라벨을 붙인다. 인용문은 내용이 실제 인용인 경우에 쓰고, 그 밖의 의미형 안내는 위 전용 형식을 사용한다. `핵심만 먼저:` 기존 quick summary도 유지한다.

## 3. 원본 HTML 작성 계약

source에는 스타일을 직접 쓰지 않는다. 위 속성은 정확한 이름과 값, 큰따옴표로 작성한다. 임의 class, style, onerror, script, data URL, 새 속성으로 꾸미지 않는다. 표현 예:

```html
<p>라벨에서 <strong>하루 섭취량</strong>과 <u>1정의 함량</u>을 구분해 확인합니다.</p>
<p><mark data-tone="key">실제 섭취량을 기준으로 비교합니다.</mark> 나머지 설명은 일반 본문으로 작성합니다.</p>
```

위 문장은 편집 표현 예시이며 개별 성분의 사용량 안내가 아니다. `<mark>` 안에는 다른 강조 태그를 중첩하지 않고 짧은 텍스트만 넣는다. 사용자가 볼 수 있는 본문은 렌더 후에도 동일해야 한다. 해설·선택·위험 안내의 의미가 강조 때문에 반대로 보이지 않아야 한다.

## 4. 밀도와 가독성

형광펜 한 구절 80자 초과, 긴 문단 전체 형광펜, mark 내부 중첩, 지나친 중첩 강조는 오류다. 형광펜 텍스트 밀도 15% 초과는 편집 검토 경고이며 임상적·통계적 품질 점수가 아니다. 한 화면이 모두 중요해 보이면 설명·배치를 다시 정리한다. 어떤 강조를 몇 개 넣어야 한다는 최소량은 강제하지 않는다. 반드시 중요한 안전정보가 있으면 일반 설명 속에 묻히지 않도록 배치한다. 필수 red_flags 답변은 danger/care 배지, contraindications 답변은 caution/danger/care 배지 안에 실제 설명을 넣어야 한다.

외래어·의학용어는 바로 풀어 설명한다. 주의·위험 문장은 분명하게 쓰되 일반 문단을 훈계·부정형으로 반복하지 않는다. 명확한 금기 표현을 문체 검사 때문에 완화하지 않는다.

## 5. 검증과 호환

`renderEditorialPost`는 source 버전으로 R3/R4를 선택한다. 테스트에서 모든 변경 없는 기존 source의 렌더 SHA256을 기준과 비교한다. R4는 의미형 강조 텍스트·색·종류·밑줄·배지·라벨의 계약을 검사한다. 허용 HTML sanitizer, staged editor HTML, 공개 페이지 검증에 같은 규칙을 연결한다.

PC/모바일 검사에서는 본문 너비 넘침, 표의 자체 가로 스크롤, 이미지 너비, 배지 라벨, 읽을 수 있는 색 대비를 확인한다. 팔레트의 일반 텍스트 대비 4.5:1을 단위 테스트하지만 이것만으로 사이트 전체 WCAG 준수를 보장하지 않는다. 실제 스킨과 공개 글은 발행 후 별도로 확인한다.

R3 이미지·대표 이미지·원출처·summary·FAQ·관련 글·자료 출처 계약은 유지한다. 이 변경에서 실제 티스토리 글을 자동 재저장하지 않는다. 다른 표시 방식이 필요하면 규격·sanitizer·렌더·공개 검사·테스트를 같이 수정한다.

근거: [W3C 색의 사용](https://www.w3.org/WAI/WCAG22/Understanding/use-of-color.html), [W3C 최소 대비](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html). 코드의 밀도·길이 경고는 프로젝트 편집 기준이지 위 기관이 정한 수치가 아니다.
