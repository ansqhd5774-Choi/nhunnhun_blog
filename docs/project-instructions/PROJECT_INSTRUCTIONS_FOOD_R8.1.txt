# 한입 건강 — 음식 카테고리 프로젝트 지침 R8.5
개정일: 2026-10-15

## 1. 대상·기준 우선순위
- 대상은 https://nhunnhun.tistory.com/ 이며 원고 저장소는 ansqhd5774-Choi/nhunnhun_blog, 실제 제출·공개 검증은 기존 공통 러너를 사용한다.
- 최신 사용자 지시와 도구 금지가 최우선이다.
- 음식의 편집·작성 기준은 이 문서와 `docs/content/FOOD_CONTENT_QUALITY_R1.md`만 사용한다.
- 다른 저장소·다른 블로그·다른 카테고리·legacy 공통 문서의 소제목·문체·복용·치료·전문가용 평가 구조를 음식 원고 판단에 사용하지 않는다.
- 공통 문서는 실행·디자인·강조·이미지·저장·발행·공개 검증의 기술 계약에만 사용한다.
- 새 작업 시작 시 최신 main SHA와 관련 기준을 확인한다. 읽지 않은 문서를 읽었다고 보고하지 않는다.

## 2. 독자와 목적
- 이 블로그의 음식 글은 일반 독자가 음식을 이해하고 선택하고 먹고 보관하는 데 도움을 주는 생활형 건강·영양 콘텐츠다.
- 글의 출발점은 독자의 실제 질문이다.
- 작성 순서는 `독자 질문 → 벤치마크 → 생활정보 조사 → 유용한 정보 선별 → 사실 확인 → 일반 독자용 작성`으로 고정한다.
- 사실 확인 과정 자체를 본문 주제로 만들지 않는다.
- 확인해서 사용할 수 없는 내용은 생략하고 독자에게 필요한 다른 생활정보를 더 조사한다.
- 실제 안전사고·알레르기·독성·금기·위험한 오해를 막기 위해 꼭 필요한 내용은 명확하게 유지한다.

## 2-1. 기존 음식 글 재작성 원칙 — 원문 격리
- 사용자가 기존 음식 URL을 지정해 `수정`, `최신화`, `재작성`, `다시 작성`, `내용 점검 후 발행`을 요청하면 기본값은 **기존 본문 수정이 아니라 전면 신규 작성**이다.
- 기존 글에서 유지하는 것은 **숫자 URL·주제·카테고리·중복 방지에 필요한 식별 정보**뿐이다.
- 기존 본문의 문장·문단·표·강조·소제목 배치·출처 목록을 새 원고의 초안이나 재료로 사용하지 않는다.
- 기존 본문을 복사한 뒤 일부 문장만 바꾸거나, 문단을 이동하거나, 표만 교체하거나, 표현을 다듬는 방식으로 전체 재작성을 처리하지 않는다.
- 새 원고는 **빈 문서에서 시작**해 `검색 의도 확인 → 정확한 키워드 벤치마크 → 새 조사 → 사실 검증 → 정보 선별 → 6개 소제목에 새로 배치 → 강조·표·이미지 재선정` 순서로 만든다.
- 새 원고가 완성되기 전에는 기존 본문을 내용 소스로 사용하지 않는다. 새 원고 완성 후 누락 점검을 위해 기존 글을 대조할 수는 있지만, 기존 내용을 되살릴 때도 반드시 새 조사로 다시 확인한 뒤 새 문장으로 작성한다.
- 사용자가 `오탈자만`, `제목만`, `사진만`, `특정 문장만`, `표 하나만`처럼 수정 범위를 명확히 제한한 경우에만 부분 수정으로 처리한다.
- 범위가 명시되지 않은 기존 음식 글 작업은 항상 **원문 격리 + 전면 신규 작성**으로 처리한다.

## 3. 사용자 확정 음식 6개 소제목
음식 글의 핵심 소제목은 아래 6개로 고정한다. 사용자의 별도 지시 없이 이름·순서·의미를 임의 변경하지 않는다.

1. 소개
2. 영양소·핵심 성분
3. 꾸준 섭취 변화
4. 궁합·시너지
5. 주의사항
6. 고르는 법·보관법

- 다른 카테고리의 소제목 체계나 과거 공통 템플릿을 섞지 않는다.
- 내부 작업 용어와 검토용 분류를 독자용 H2로 사용하지 않는다.
- 각 H2 첫 문장은 일반 독자가 바로 이해할 수 있는 직접 답변이어야 한다.

## 4. 각 소제목의 역할
### 1) 소개
- 음식의 정체, 이름, 종류, 맛·식감, 제철·산지, 실제 유통 형태처럼 처음 보는 독자가 알아야 할 기본 정보를 다룬다.

### 2) 영양소·핵심 성분
- 중요한 영양소와 핵심 성분을 설명하고 그것이 몸에서 어떤 역할을 하는지 쉬운 말로 연결한다.
- 숫자 나열이나 일반 영양표만으로 소제목을 채우지 않는다.

### 3) 꾸준 섭취 변화
- 일상 식사에서 꾸준히 먹을 때 기대할 수 있는 현실적인 장점과 활용을 설명한다.
- 확인해서 사용할 수 없는 효능은 만들지 않고 실제 활용·선택·식사 가치가 높은 정보를 더 찾는다.

### 4) 궁합·시너지
- 무엇과 같이 먹으면 좋은지, 왜 좋은지, 실제로 어떻게 먹을지 설명한다.
- 영양 보완·흡수 도움·맛과 식감의 조화를 구분해 과장 없이 설명한다.

### 5) 주의사항
- 알레르기, 과다섭취, 특정 질환·상황, 독성, 약물과의 중요한 상호작용 등 독자가 실제 행동을 바꿔야 하는 내용만 넣는다.
- 일반적인 부정·제한 설명으로 분량을 채우지 않는다.

### 6) 고르는 법·보관법
- 신선도, 구매 기준, 제품 형태 차이, 보관 위치·기간·방법, 손질·조리 시 실용 팁을 다룬다.

## 5. 조사와 벤치마크
- 먼저 일반 독자가 실제로 묻는 질문과 좋은 음식·건강 콘텐츠가 공통으로 다루는 정보 범위를 확인한다.
- 벤치마크는 문장이나 주장을 복사하기 위한 것이 아니라 빠진 질문과 실용 정보를 찾기 위한 절차다.
- 맛·식감·제철·산지·유통·먹는 법·제품 차이·보관처럼 생활에 필요한 정보를 폭넓게 조사한다.
- 수치·영양·건강·안전 정보는 신뢰 가능한 자료로 사실 여부를 확인한다.
- 검색 스니펫·AI 요약만으로 수치나 건강정보를 확정하지 않는다.
- 사실 확인에 사용한 자료의 종류와 확인 과정은 독자에게 필요하지 않으면 본문에 설명하지 않는다.

## 6. 정보 밀도와 표
- 각 핵심 문단은 독자에게 새로운 사실·선택·행동 중 하나 이상을 제공해야 한다.
- 같은 내용을 도입·표·본문·요약에서 표현만 바꿔 반복하지 않는다.
- `100mL → 200mL`, `1개 → 2개` 같은 단순 배수·단위 환산으로 표를 늘리지 않는다.
- 표는 각 행·열이 서로 다른 선택 정보를 제공할 때만 사용한다.
- 내용이 부족하면 표·강조·문장 수를 늘리지 말고 조사를 확장한다.

## 7. 긍정·실용 중심의 본문 균형
- 글의 첫인상과 대부분의 본문은 음식의 특징, 영양, 장점, 실제 활용, 선택, 섭취 행동을 중심으로 한다.
- 부정·제한·반박 문장이 글 전체를 지배하지 않게 한다.
- 안전상 반드시 필요한 주의는 5번 소제목에 집중하고, 다른 소제목에서 반복하지 않는다.
- 독자의 행동에 꼭 필요하지 않은 부정 설명은 본문에 추가하지 않는다.

## 8. 쉬운말
- 전문용어보다 일상적인 한국어를 우선한다.
- 기관명·DB명·전문 방법명·통계용어는 독자 판단에 필요하지 않으면 본문에서 빼고 출처에 둔다.
- 전문명이 필요하면 쉬운 설명을 먼저 쓰고 한 번만 보조한다.

## 9. 강조·이미지·내부링크
- 기존 direct/SP1 디자인과 3단계 강조 시스템을 사용한다.
- 강조는 확인된 장점, 핵심 성분의 역할, 실제 섭취·선택·보관 행동, 꼭 필요한 안전 행동을 우선한다.
- **굵은 글씨는 3단계 중 가장 낮은 강조로 보고 적용 문턱을 낮춘다.** 독자가 훑어볼 때 먼저 잡아야 할 긍정적인 특징·장점·영양상 이점·좋은 궁합·맛과 활용상의 강점·실용적인 선택 및 섭취 팁에는 자연스럽게 사용할 수 있다.
- 긍정적인 내용이라도 문단 전체를 굵게 만들지 말고, 핵심 단어·짧은 구절·핵심 결론만 골라 강조한다.
- 굵은 글씨·형광펜·밑줄의 개수를 목표로 맞추지 않는다. 특히 굵은 글씨를 늘리기 위해 새 문장이나 근거 없는 장점을 만들지 않는다.
- 형광펜과 밑줄은 굵은 글씨보다 높은 단계로 유지하며, 확인된 핵심 장점·중요한 실천 행동처럼 실제 우선순위가 높은 내용에만 사용한다.
- 부정 문장·제한 문장·검토용 표현을 강조 개수 채우기용으로 사용하지 않는다.
- 신규 및 전체 수정은 서로 다른 관련 본문 이미지 최소 3개를 사용한다.
- 내부링크는 실제로 관련된 기존 음식 글만 사용한다.

- 사용자 확정 6개 소제목을 유지했는가?
- 일반 독자가 추가 검색 없이 핵심 내용을 이해할 만큼 정보가 충분한가?
- 장점·활용·선택·섭취·보관 정보가 충분한가?
- 사실 확인 과정이 독자용 본문을 차지하지 않는가?
- 확인해서 사용할 수 없는 내용 대신 다른 유용한 정보를 충분히 조사했는가?
- 같은 사실이나 단순 산술값을 반복하지 않았는가?
- 주의사항이 다른 소제목을 침범하지 않는가?
- 각 H2 첫 문장이 독자의 질문에 바로 답하는가?

## 11. 실행·완료
- 음식 원고 작성·수정은 direct/SP1 경로만 사용하며 Queue/Ollama 작성 경로를 사용하지 않는다.
- 신규: `posts/*.json` → `publish-posts.yml`
- 기존 수정: `updates/direct-*.json` → `direct-author-update.yml` → `update-posts.yml`
- 기존 수정의 기본 편집 방식은 부분 패치가 아니라 `2-1. 기존 음식 글 재작성 원칙`에 따른 전면 신규 작성이다.
- 실제 제출 시작 뒤에는 해당 source나 실행 코드를 임의 변경하지 않는다.
- HTTP 200, 제출 클릭, Actions SUCCESS만으로 완료라고 하지 않는다.
- source별 `PUBLIC_VERIFIED`와 신규 `published` 또는 기존 `updated` 원장을 확인한다.
- 불명확 제출 상태에서는 중복 재제출하지 않고 기존 source·원장·실행 상태부터 확인한다.

## 12. 도구·보안·변경 보호
- TinyFish, Browserbase 발행, Remote Desktop Commander 발행, Ollama 작성·강조 생성을 사용하지 않는다.
- 사용자에게 Node·CMD·gh·Chrome·GUI 조작을 요구하지 않는다.
- 비밀번호·OTP·CAPTCHA·쿠키·토큰·인증 헤더를 대화·원고·로그·Git에 노출하지 않는다.
- 승인 없는 삭제·URL 변경·권한 확대·유료 가입·스킨/광고 변경·force push·reset·비공개→공개 전환을 하지 않는다.
