# 백업과 rollback 기준

백업 단위는 스킨 패키지 / 글 원문 / 카테고리·설정이다. 스킨 ZIP 하나로 글·댓글·광고 계정·플러그인 설정을 복원할 수 없다. 현재 ZIP의 skinSettings.set와 sidebar.info가 모든 플랫폼 설정 복원을 보장하지 않는다. 외부 CDN 스크립트와 폰트도 ZIP에 포함된 것으로 간주하지 않는다.

적용 금지 조건: 최신 원본 없음, 해시 불일치, 후보 파일 누락, 적용 대상 불명확, 복구 권한/경로 없음, 편집 중 타 작업 충돌. 해당 범위만 BLOCKED로 기록한다.

복구 트리거: 변경 직후 본문 누락, 메뉴/검색 불능, PC·모바일 주요 화면 붕괴, 새로운 JS 오류로 기능 중단, 광고가 콘텐츠를 가림, canonical/robots 잘못 변경, 사용자 STOP 요청. 기존에 있던 문제는 새 회귀와 구분한다.

복구 절차:

1. 추가 적용을 중단하고 변경 대상·마지막 정상 백업·증거를 확인한다. 사용자에게 영향과 복원 대상을 알린다.
2. HTML/CSS 수정은 관리자 ‘스킨 편집 → HTML 편집’의 해당 탭에서 백업 원문만 복원한다. 이미지/파일 또는 전체 스킨 변경은 ‘스킨 변경’의 스킨 등록/보관함 등 현재 UI의 공식 복구 경로를 사용한다. 메뉴는 실제 화면에서 다시 확인하며 이름을 추정해 클릭하지 않는다.
3. 복원 전 현재 상태를 별도 보존한다. ZIP 복원이라면 내부 파일 12개와 구조를 확인하고 플랫폼 안내대로 등록한다. 전체 스킨 적용이 사용자 옵션을 바꿀 수 있으므로 이전 옵션/사이드바도 대조한다.
4. 글 수정은 해당 글의 백업 제목·본문·태그·카테고리·발행 상태만 복원한다. 카테고리 변경은 매핑표에 따른 글 소속과 이전 이름을 복원한다. 불필요하게 스킨 전체를 교체하지 않는다.
5. 한 번 복원 후 홈·대상 글·카테고리·PC/모바일을 검사한다. 실패하면 반복 적용하지 않고 STOP, 상태와 사용자 수동 공식 경로를 보고한다.
6. 복구 시각·원본 해시·실사이트 결과를 changes/에 남긴다.

현재 상태: 로컬 ZIP 추출과 해시 검사는 가능. 운영 rollback 적용은 하지 않았으며 복구 성공 미검증. 최초 설정 작업에서는 사이트를 변경하지 않았다.
