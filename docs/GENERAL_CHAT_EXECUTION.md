> 네 카테고리 공통 기반: [음식 기반 공통 작성 계약](content/CATEGORY_CONTENT_PARITY.md)을 적용한다. 내용과 소제목만 분야에 맞게 바꾸며 강조·디자인·러너·발행·공개 검증은 동일하게 유지한다. 신규와 기존 전체 수정에 공통 적용한다.

> 블로그 방향·제목: 한입 건강은 건강·영양 정보 블로그이며 조리·레시피 전문 블로그가 아니다. 음식 제목은 본문의 중심인 영양·칼로리·섭취·궁합·주의·선택·보관에 맞춘다. 조리법은 안전한 섭취·활용을 돕는 보조 내용이며, 사용자의 명시적 조리법 요청 없이 ‘만들기’를 제목의 주된 약속으로 선택하지 않는다. 제목·본문의 중심이 어긋나면 건강정보 방향에 맞게 제목을 먼저 조정한다. 상세 기준: [제목 선정 계약](content/HEALTH_TITLE_SCOPE.md).

> 사용자 도구 금지: TinyFish 사용·호출·연결·승인 요청은 금지한다. Fetch Content, 조사·공개 조회·관리자 진단·fallback에도 적용하며, 다른 문서의 허용 문구보다 이 금지가 우선한다. 허용된 GitHub·러너 경로로 진행하고 접근 제약을 금지 도구 승인 요청으로 전환하지 않는다.

# 일반 Chat 작성·러너 실행 계약

일반 Chat과 Codex 모두 이 역할 분리를 따른다. 기존 문서의 작성자 로컬 명령·브라우저·미리보기 의무, 사용자 공개 확인 의무, 과거 실행 경로와 충돌하면 이 문서가 우선한다. 콘텐츠 의미·강조 기준은 DIRECT_AUTHORING_R1 또는 해당 R1 기준을 유지한다.

## 작성자

신규와 기존 수정 모두 DIRECT_AUTHORING_R1의 ‘저장 전 내용 검토’를 적용한다. 소제목 적합성, 장점 중심 문체, 주장별 원문 연결, 중복 설명, 실행 가능한 조리·보관 문구를 작성 중 반영하고 저장 전 한 번 확인한다.

### 검색 의도·정보 밀도 재발 방지
- 원고를 쓰기 전에 해당 키워드를 검색한 독자의 **핵심 질문을 최대 6개**로 확정한다. 음식·영양소·약학·질병의 여섯 핵심 역할을 이 질문에 맞춰 합쳐 표현하며, 같은 질문을 세부 기전·용어 차이·연구별 결과 때문에 여러 H2로 쪼개지 않는다.
- `자주 묻는 질문`, `핵심 정리`, `함께 보면 좋은 글`, `자료 출처`는 보조 영역이며 핵심 질문 수에 포함하지 않는다.
- 어떤 문단을 빼도 독자의 핵심 질문 답변·실천 행동·필수 안전정보가 달라지지 않는다면 본문에서 삭제하거나 자료 출처 수준으로 낮춘다.
- 연구 설계·표본 수·통계값·시험명은 독자의 섭취·복용·진료 결정에 직접 필요한 경우만 남긴다. 일반 건강정보 글에서 논문 설명 자체가 별도 대주제가 되지 않게 한다.
- `근거가 부족하다`, `단정하기 어렵다`, `확립되지 않았다` 같은 한계 문구를 효능·소개·FAQ에 반복하지 않는다. 실제 안전 행동은 주의사항에 분명히 남긴다.
- 새 direct SP1 제출은 `prepare-selected-source`에서 **핵심 H2 6개 초과**, **연구보고식 표현 과다**, **안전 항목 밖 근거 한계 반복**을 결정론적 구조 검사로 차단한다. 이 검사는 의학적 의미·진실성을 자동 판정하거나 문장을 자동 재작성하지 않는다.

연결된 자료 도구로 조사하고 원고·강조·내부링크·이미지 근거를 함께 준비한다. GitHub 저장과 결과 읽기 기능은 현재 연결에서 확인한다. 원고 저장은 발행 성공이 아니다. 일반 Chat에 사용자 PC의 Node, CMD, gh, Chrome, GUI, 로컬 HTML 파일 열기를 요구하지 않는다. 필요한 연결 기능이 없으면 해당 단계의 접근 제약을 보고하며 발행 실패로 단정하지 않는다.

사진은 3장 이상 사용하고 HTTPS, alt, 원출처·저작자·라이선스 및 중복 여부를 검증한다. 실제 시각 검토는 발행 필수 조건이나 차단 사유가 아니다. 러너의 태그 검사는 글의 의료적 의미나 사진의 내용을 검토한 결과가 아니다.

## 제출과 실행

- 기존 수정: 완성된 승인 원고를 updates/direct-*.json의 main에 저장하면 direct-author-update가 기존 update-posts로 전달한다. 자동 실행이 있으면 그 실행을 관찰한다. 수동 실행을 겹쳐 호출하지 않는다.
- 신규: posts/*.json의 승인 원고는 기존 publish-posts 경로를 사용한다. start-direct-publish CLI는 기존 수정 운영자용이며 신규 공통 진입점이 아니다.
- 초안은 자동 발행 대상에 ready/approved로 저장하지 않는다. updates는 draft 계약을 지원하지 않으므로 초안은 별도 작업 경로/브랜치에 보존한다.
- prepare-selected-source를 기존 러너 단계에서 실행해 보안·렌더 준비·강조 현황·독자 중심 구조를 확인한다. 작성자는 출력된 문구를 실제 의미 검토 증거로 과장하지 않는다. 로컬 prepare 실행은 선택적인 운영자 보조 도구다.

## 예약 GPT 작업 장애 격리와 사전검사

- 여러 글을 미래 시각에 처리할 때는 **글 1건 = 독립 1회성 ChatGPT 예약 작업**으로 만든다. 서로 다른 글을 하나의 RRULE/COUNT 반복 작업에 묶지 않는다. 외부 앱 쓰기 승인·안전 검사에서 한 실행이 정지되더라도 이후 글의 예약까지 연쇄 중단되지 않아야 한다.
- 예약 실행에서는 원고 전체를 완성하기 전에 사용할 사진의 HTTPS, alt, 원출처·라이선스를 확인한다. 실제 시각 관찰 여부는 승인 저장·발행을 차단하지 않는다.
- GitHub 쓰기 액션이 실제 커밋 생성 전에 연결 앱의 승인·안전 검사에서 거부되면 상태를 `WRITE_NOT_COMMITTED`로 구분한다. GitHub API 권한 오류·GitHub CI 실패·Tistory 실패와 같은 원인으로 합치지 않는다.
- `WRITE_NOT_COMMITTED`에서는 저수준 Git/GitHub 객체 조작이나 수동 workflow_dispatch로 우회하지 않는다. 가능한 경우 완성 원고를 대화/파일 작업물로 보존하고, 독립된 다음 예약 작업은 그대로 진행되게 한다.
- GitHub 저장 성공은 대상 파일 존재와 **새 main 커밋 SHA**를 실제 확인한 경우에만 선언한다. 원고 작성 완료나 쓰기 요청 시도만으로 저장 완료라고 하지 않는다.
- push로 자동 Actions가 시작된 작업은 동일 source의 수동 workflow_dispatch를 겹쳐 호출하지 않는다.
- `TISTORY_CHROME_READY`는 전용 Chrome/CDP가 연결 가능하다는 뜻일 뿐 로그인 성공 증거가 아니다. 신규·기존 mutation은 읽기 전용 사전검사에서 `TISTORY_AUTH_READY`가 확인된 뒤에만 시작한다. 로그인 페이지로 이동하거나 글쓰기 컨트롤을 확인하지 못하면 `E_TISTORY_AUTH_REQUIRED_PRECHECK`로 최종 제출 전에 중단한다.

## 검색·갱신 후속 운영

[32개 운영 계약](HEALTH_GROWTH_OPERATIONS.md)은 작성/발행 계약을 대체하지 않는다. 일반 Chat에 로컬 검색 점검 CLI·브라우저 기능을 요구하지 않고, 운영자가 만든 결과와 연결된 공식 도구를 읽는다. Google·네이버·Bing 등록/색인/유입은 공개 검증과 별도 상태다.

## 결과 확인

러너가 실행·제출·공개 검증을 담당한다. 일반 Chat은 GitHub 실행 로그 및 publishing/state 또는 publishing/update-state의 해당 source 기록을 읽는다. 기존 수정은 publicResult에 source ID, fingerprint, sourceCommit, runUrl, checkedAt, status, 검증 항목을 기록한다. 원장 경로는 발행 trigger 대상이 아니므로 결과 기록이 새 원고 발행을 시작하지 않는다.

- PUBLIC_VERIFIED: 해당 원고 제목·전체 본문·이미지·대표 이미지·direct 강조·PC/모바일 확인 완료, updated 전환.
- PUBLIC_VERIFICATION_UNAVAILABLE: 조회/자산 접근 불가. submitting 보존, 재제출 없음.
- PUBLIC_VERIFICATION_MISMATCH: 실제 비교 불일치. submitting 보존, 저장 실패 단정·재제출 없음.
- Actions 실패와 위 상태를 함께 읽는다. SUBMIT_CLICKED는 제출 클릭 증거이고 공개 반영 완료가 아니다.

기존 submitting 공개 재확인은 update-posts에서 update=false와 기존 source_id로 수행한다. 편집기 접근·mutation 없이 원격 원고 및 원장과 익명 공개 결과를 대조한다. 결과가 불명확하면 중복 수정하지 않는다. public_verify_article_ids는 과거 호환 입력이며 현재 source_id를 사용한다.

최초 러너 등록·로그인·PC/Chrome 유지와 스킨 원본 백업·관리자 조작은 운영자 작업이다. 이를 매 글 일반 Chat의 완료 조건으로 요구하지 않는다. 승인·URL 보호·HTML 보안·source drift·인증·중복 제출 방지는 유지한다. 결과 기록이나 연결 권한 없이 완료라고 보고하지 않는다.
