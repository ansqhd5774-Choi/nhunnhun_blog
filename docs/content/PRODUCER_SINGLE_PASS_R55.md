# R5.5 단일 작성 자동 수정

## Ollama 원고 검사 제거 (2026-10-08)

SP1 자동 원고에는 내용·효능·근거·길이·섹션 수·강조·표·요약·출처 배치에 대한 Editorial/Content 검사를 실행하지 않는다. Producer는 생성 원고를 취합하며 dry-run 결과는 DRY_RUN_GENERATED로 기록한다. CONTENT_VALIDATION_SKIPPED는 검사 PASS가 아니다. 생성 응답 수신/JSON 읽기, 빈 원고, 대상 URL/승인/해시·source drift/중복 제출/HTML 보안/이미지 라이선스와 발행 결과 확인은 실행·보안 보호로 유지한다. 기존 수동 R1 원고에는 이 예외를 확대하지 않는다. Queue의 코드 테스트는 PR에서만 실행하며 실제 생성 작업의 선행 조건으로 두지 않는다.

## 음식 카테고리 최종 사용자 작성안 (2026-10-08)

음식은 아래 항목을 각각 독립된 Ollama 요청으로 순서대로 생성하고 취합한다. 요청마다 user 메시지 하나만 전달하며 별도 system 지시·조사 자료·이전 항목 응답을 붙이지 않는다. 이 경로는 웹 조사를 수행한 원고로 간주하지 않는다. 영문 주제는 기존 evidence.query를 사용한다. 글자수는 전달용 목표이며 결과 길이에 따른 차단·축약·재작성·의미 검토를 하지 않는다. 각 항목별 캐시로 성공한 생성은 재사용하며 기술적 실패 시 기존 오류 처리로 종료한다.

| 번호 | 제목 | 약 글자수 | 형식 | 내용 |
|---|---|---|---|---|
| 1 | 소개 | 250 | 서술형 | 한국 제철 정보, 특징 |
| 2 | 영양소와 핵심 성분 | 400 | 서술형, 기본표, 핵심표, 효과 | 표(성분,일일영양소) |
| 3 | 꾸준히 먹으면 신체 변화는? | 400 | 서술형, 핵심 효과(요약형) | 구체적이고 논리적인 효과 |
| 4 | 궁합이 잘 맞는 음식과 시너지 효과 | 400 | 서술형, 핵심 효과 | 구체적이고 논리적인 효과 |
| 5 | 섭취 시 주의사항 | 400 | 서술형, 요약형 | 구체적이고 논리적인 효과 |
| 6 | 좋은 {keyword} 고르는 방법과 보관 | 400 | 서술형, 요약형 | 구체적이고 논리적인 효과 |

6번 제목만 작업 키워드에 맞게 치환한다. Markdown 표·불릿·굵은 글씨를 HTML로 변환하며 원본은 캐시 및 draft artifact에 보존한다. SP1은 생성 영수증이며 사실 검증 PASS를 뜻하지 않는다. 기존 URL·source drift·승인·중복 방지·이미지·HTML·공개 확인은 유지한다. 나머지 카테고리는 기존 전체 1회 작성 정책을 유지한다. 아래 단일 작성 설명 중 음식과 충돌하는 부분은 이 최종 작성안을 우선한다.

사용자 요청에 따라 기존 URL Queue는 조사 1회 → 질문 6개와 목표 글자수 → Ollama 전체 작성 1회 → 기술 검사 → 기존 update workflow → 공개 확인으로 처리한다. 목표 글자수는 정보량 안내이며 문단 수와 내부 H2 ID를 강제하지 않는다.

AI Plan, claim/type/risk/sourceIds 출력, 의미 검토, 강조 선택 호출, 자동 재검색·절 보완·재작성은 운영 경로에서 사용하지 않는다. 이전 함수는 기존 기록·회귀 호환용이며 신규 Producer에서 호출하지 않는다. 캐시는 같은 입력 재실행의 생성 호출을 생략한다. 미등록 주제의 영문명 변환은 최대 짧은 1회 호출이 별도로 발생할 수 있다.

내용 품질 문제는 사용자 판단으로 재작성을 요청한다. SP1 source는 실제 내용 검토를 수행했다는 R1 PASS를 만들지 않고 생성 영수증에 semanticReview=not-performed를 기록한다. SP1은 auto-숫자-r55 기존 수정 source에만 허용한다. 기존 R1 검사와 신규 발행 기준은 유지한다. SP1은 기존 R3 HTML renderer를 사용하며 의미형 강조 검사는 적용하지 않는다.

대상 URL/제목, 승인, source drift, 중복·불확실 제출, 이미지 기존 검토 기록, HTML 안전성, 원장·공개 검증은 유지한다. 기술 실패는 ERROR_SYSTEM으로 저장 후 종료하며 내용 오류의 자동 반복 재시도는 없다. 과거 BLOCKED도 자동 재시도하지 않는다.

로컬 테스트: node authoring/update-producer.mjs --dry-run --article=327. 공개 변경 없는 실제 시험에서 qwen3:4b 작성 호출 1회(27.2초)와 기술 검사가 완료됐다. 전체 조사 포함 시간은 metrics artifact로 측정한다. 동일 품질·분량 대비 개선 수치로 해석하지 않는다. 실제 티스토리 수정은 별도 운영 증거가 필요하다.

## 구체 정보·분량 보강
네 분야 기존 질문 순서를 유지하며 항목별 400·500·450·350·350·250자(본문 합계 약 2300자), 도입·요약 포함 약 2500자를 안내한다. 분야별 include로 영양 수치·기준량·단위·대상·기간·조리·선택·주의 조건 등 자료 기반 구체 정보를 전달한다. 숫자가 없으면 임의 생성하지 않는다. 글자수는 목표이며 분량 부족으로 차단하거나 자동 재작성하지 않는다.

## 음식 항목별 강조 지시 (2026-10-08)

음식 6개 독립 요청 모두에 다음 지시를 추가한다. 키워드·영문명은 작업 대상에 맞게 치환한다.

- 핵심 단어 굵은 글씨 적용 (**단어**)
- 중요한 문구 형광펜 적용 (==문구==)

강조 문구는 Ollama가 선택한다. 변환기는 **단어**를 strong으로, ==문구== 또는 단순 mark 태그를 기존 형광펜 렌더러용 u로 변환한다. 형광펜 색상은 기존 노랑·연두·파랑·분홍 순환을 사용한다. 추가 AI 검토·강조 개수 검사·재작성은 하지 않는다. 기존 공개 글을 자동으로 수정하지 않는다.

## SP1 이미지 선택과 배치

외부 이미지 사용 권한 및 출처 기록은 유지한다. 시각 검토 플래그·hero·closeup·3개 필수는 강제하지 않는다. 6개 항목 취합 후 동일 Actions 실행 안에서 항목별 Commons 검색을 한 번씩 수행한다. 검색어는 evidence.query의 주제와 항목별 검색 단어로 코드가 구성하며 추가 Ollama 호출은 하지 않는다. 파일 제목이 해당 주제를 식별하고 저작자·원출처·허용 라이선스가 있는 사진을 항목당 0~1개 선택한다. 같은 원본 파일은 중복 사용하지 않으며 원출처·저작자·라이선스를 본문에 기록한다. 검색 실패는 기록하고 계속한다. 새 사진이 전혀 없으면 저장소의 동일 주제 이미지를 재사용하고, 그것도 없으면 수정 시 기존 본문의 첫 사진을 보존한다. 기존 대표이미지 설정은 변경하지 않는다. SP1 표는 고정 최소 폭 대신 유동 폭·긴 텍스트 줄바꿈을 적용한다. 공개 확인·내용 검사·재작성 호출을 추가하지 않는다.
