### 저장 전 내용 검토 — 신규·기존 수정 공통
- 제목과 각 소제목이 실제 본문에서 직접 답하는 내용과 일치하는지 확인한다.
- 소개·효능·궁합은 확인된 장점과 작용을 먼저 설명한다. 주장하지 않은 치료 효과를 굳이 반박하거나 각 문단에 ‘아니다/근거 없다’를 반복하지 않는다. 실제 위험과 중요한 적용 조건은 유지한다.
- 흡수·상호작용·효과 크기처럼 구체적인 연구 주장은 해당 원문 출처와 연결한다. 일반 영양 보완과 특정 조합의 직접 인체 연구 결과를 구분한다. 확인하지 않은 근거를 만들지 않는다.
- 상세 수치와 자료 기준은 영양 항목에 모으고, 다른 항목에서는 필요한 행동만 간결하게 설명한다. FAQ·요약의 독립적인 핵심 답은 유지한다.

- 작성 중 본문·근거·강조·내부링크를 함께 반영하고 저장 직전 한 번 검토한다. 이 검토를 자동 의미 판정, 추가 CI 차단, 자동 재작성 루프로 만들지 않는다.
- 내용 검토 결과와 기술 검사·PUBLIC_VERIFIED를 따로 보고한다. 공개 검증은 원고 반영·렌더 검사이며 의학적 의미 검토 완료를 뜻하지 않는다.

### 장점과 활용을 직접 설명하는 문체 — 2026-10-09 수정
- 소개는 맛·특징·제철, 영양은 성분과 역할, 신체 변화는 근거 있는 생리 기능, 궁합은 구성 보완·흡수 작용을 먼저 설명한다. 모든 효능 설명에 부정·반박·한계 문장을 붙이는 방식을 폐기한다.
- 자료의 품종·생것/조리 상태·기준량은 영양표 바로 앞에 간결하게 표시한다. 같은 자료 범위를 소개와 다른 항목에서 반복하지 않는다.
- 신체 변화의 소항목에는 영양소의 신체 내 역할을 배치한다. 조리법과 보관법은 해당 항목으로 옮긴다.
- 형광펜은 독자가 기억할 성분의 역할·궁합의 작용·실천 기준을 강조한다. 일반 효능 문단에서 반박 문구를 강조 대상으로 고르지 않는다.
- 알레르기·독소·응급 증상 등 실제 안전 경고는 주의사항에 명확하게 남긴다. 사실의 범위 안에서 설명하며 확인되지 않은 치료·예방 효과는 만들지 않는다. 반복 부정문 제거를 위해 안전 경고를 삭제하거나 근거 없는 긍정 표현으로 바꾸지 않는다.

승인 디자인: 주황색 포인트, 회색 요약 카드, PC 카드 3열·모바일 1열, 제목 아래 주황 선, 명확한 목차, 대표 사진 상단. 긴 설명은 일반 문단, 항목별 핵심 내용은 `<ul><li><strong>항목명</strong>설명</li></ul>`로 작성한다. 표에는 실제 필요한 수치만 간결하게 배치한다. 문장 끝 콜론과 번호를 카드 항목명에 넣지 않는다.

강조: 1단계 `<strong>`, 2단계 `<mark><strong>`, 3단계 `<mark><u><strong>`를 GPT가 원문 의미에 맞게 선택한다. 기존 글의 문장 내용은 디자인 때문에 자동 변경하지 않는다.

### 강조 누락 방지 — 작성과 동시에 적용
최신 사용자 지시: 강조 범위를 확대한다. 독자가 강조 부분만 훑어도 각 항목의 핵심 정보와 실천 방법을 파악할 수 있게 선택한다. 몇 단어만 꾸미는 방식이나 최소 개수만 채우는 방식으로 축소하지 않는다.
- 소개: 주제의 특징·제철·종류 차이를 강조한다.
- 영양: 주요 성분명뿐 아니라 기준량·함유량·단위·성분의 역할을 함께 강조한다. 표의 핵심 수치에도 적용한다.
- 신체 변화: 구체적인 변화·작용과 그 변화가 적용되는 섭취 조건을 강조한다.
- 궁합: 조합명뿐 아니라 어떤 성분을 보완하고 어떤 흡수·상호작용에 관여하는지 설명하는 구절까지 강조한다.
- 주의사항: 주의 대상·상호작용·실제 피하거나 조절할 행동을 강조한다.
- 선택·보관: 제품 비교 기준·보관 온도와 기간·상태 판단·실천 방법을 강조한다.
한 문장에 핵심 정보가 여러 개 있으면 여러 구절에 적용할 수 있다. 짧은 문장 전체가 하나의 핵심 조건이면 문장 전체를 강조할 수 있다. 긴 문단에서는 핵심 구절을 넓게 선택하되, 주변 설명과의 시각적 차이를 유지한다. 같은 이유로 모든 문단 전체를 자동 처리하거나 태그 개수·비율을 고정하지 않는다.
- 1단계는 독자가 찾는 성분명·음식명·핵심 단어에 `<strong>문구</strong>`를 사용한다.
- 2단계는 핵심 수치·효과의 조건·음식 궁합의 작용 설명에 `<mark><strong>문구</strong></mark>`를 사용한다. 형광펜만 단독으로 넣어 굵은 글씨가 빠지는 것을 피한다.
- 3단계는 행동을 결정하는 중요한 섭취·안전·보관 조건에 `<mark><u><strong>문구</strong></u></mark>`를 사용한다. 밑줄만 넣어 3단계 적용을 대신하지 않는다.
- GPT가 여섯 항목을 쓰면서 강조할 구절을 함께 선택한다. 제목이나 카드 배치가 강조 선택을 대신하지 않는다. 문구의 중요도에 따라 적용하며 숫자 할당량을 채우려고 문장을 추가하지 않는다.
- 항목별 강조 현황은 러너의 선택 원고 준비 결과로 확인한다. 의미 검토는 작성자가 수행하며 기술 PASS로 대체하지 않는다.

### 작성 시간 단축
껌 `/39` 점검에서 공개 반영은 확인됐지만 형광펜 1곳은 굵은 글씨 없이 저장됐고 2·3단계 중첩은 없었다. CSS가 원고에 없는 강조 의미를 생성하지 않으므로 작성 단계에서 보완한다. 기존 전체 개수 관찰만으로 각 항목의 누락을 확인했다고 간주하지 않는다.

저장 전 같은 `emphasis-summary` 명령의 `sections`를 한 번 읽는다. `standaloneHighlights`는 단독 형광펜의 실제 문구를 보여준다. 각 항목의 핵심 수치·작용 조건·주의 행동을 작성자가 확인하고 필요한 중첩 태그를 그 자리에서 보완한다. 적용 대상이 없는 항목에 개수를 강제하지 않는다. 본문·사진·근거를 다시 조사하지 않고 강조 태그만 보완하며, 출력은 PASS/FAIL 판정이 아니다.

공개 확인은 러너의 익명 검증 결과와 원장을 읽는다. 조회 불가를 제출 실패로 단정하지 않으며 submitting은 읽기 전용 재확인으로 처리한다. 일반 Chat에는 직접 브라우저 비교를 요구하지 않는다.

1. 기존 글·재사용 가능한 자료·내부링크를 먼저 확인하고, 여섯 항목에 필요한 조사 요청은 서로 독립적인 경우 한 번에 묶는다. 새 주장의 근거가 필요한 경우에만 추가 조사한다.
2. 한국어 본문·강조·내부링크를 한 번에 작성한다. 사진은 대표 사진을 먼저 확정하고, 설명 가치가 있는 본문 사진만 추가한다. 유효한 기존 사진 확인 결과를 재사용한다.
3. 승인된 공통 렌더러와 CSS를 재사용한다. 글마다 스킨 변경이나 새 디자인 시안을 만들지 않는다. 강조 현황은 저장 직전에 한 번 관찰한다.
4. 원고를 한 번 저장하고 해당 변경에 필요한 기술 검사만 실행한다. 기존 유효한 검사 결과를 반복 실행하지 않는다. 발행은 기존 진입 명령으로 한 번 실행하고 기존 run을 관찰한다.
5. 시작 / 자료 준비 완료 / 원고 저장 / 발행 실행 / SUBMIT_CLICKED 시간을 한국시간으로 기록한다. 전체 시간은 시작부터 최종 제출까지, 조사·작성·실행 대기·발행 시간은 각 경계의 차이로 보고한다. Actions 실행 시간만 전체 작성 시간으로 표시하지 않는다. 측정 전 절감률을 확정 수치로 보고하지 않는다.

사진: 대표 사진 1개 필수. 현재 도구로 직접 확인하거나 유효한 시각 검토 기록을 재사용하고 주제가 사진의 중심인 파일을 고른다. 사진은 본문 첫 `<p><img src="..." alt="..."></p>`와 representativeImageUrl에 같은 주소로 저장한다. 본문 사진은 항목에 설명 가치가 있을 때 추가하며 같은 사진을 반복하지 않는다. 원출처·권한은 JSON 내부에 기록하며 자료출처/이미지출처 섹션을 자동 추가하지 않는다. 이번 감자 예시는 direct-photo-example.json에 저장했다.

## 실행
발행 전 러너가 선택 원고 준비·실제 발행 HTML 검사를 수행한다. 작성자 로컬 실행이나 로컬 파일 열기를 필수로 요구하지 않는다.
1. GPT가 `updates/direct-{articleId}-{작업일}.json`을 작성. 기존 update 스키마, contentStandard=SP1, 실제 승인 source만 ready/approved=true로 저장한다.
2. 원문은 안전한 기본 HTML로 저장한다. class/style/script를 원문에 넣지 않는다.
3. publishing/direct-design.mjs가 보안 검사 후 승인한 레이아웃을 조립한다. 스킨 CSS는 css/proposals/2026-10-09-direct-reference-design.css와 동일하게 유지한다.
4. 최신 main 저장 후 direct-author-update 자동 전달과 update-posts 실행을 관찰한다. 신규 posts는 publish-posts를 사용한다.
5. source drift·대상 URL·중복/불명확 제출·HTML 보안 보호를 유지한다. 내용 검사·재작성 루프는 추가하지 않는다. 최종 클릭 후 공개 검증과 원장 최종화는 러너가 한다.

단순 키워드 등록만으로 무인 GPT 작성이 시작된다고 보고하지 않는다. 생성 원고 준비는 현재 대화의 GPT가 수행한다.

## 발행 연결 누락 방지
발행 요청은 원고 저장·기술 CI에서 끝내지 않는다. 자동 전달의 실행 결과와 해당 source 원장을 읽는다. 운영자용 start-direct-publish는 기존 수정 전용이며 일반 Chat 필수 도구가 아니다.

보고 상태는 원고 저장 / 기술 CI 통과 / 발행 실행 URL / 최종 제출 완료로 구분한다. CI 성공은 발행 성공이 아니다. 실행 URL이 없으면 실행 확인 안 됨으로 보고하고 자동 재호출하지 않는다. 실패/불명확 제출 기록이 있으면 로그를 먼저 분석한다. 일반 Chat은 현재 연결에서 제공하는 원격 결과 읽기 경로를 사용하며 CLI·UI를 필수 대체 경로로 요구하지 않는다.

### CI 취소와 시간 낭비 방지
자동 전달에서 `E_DIRECT_PUSH_SOURCE_COUNT`가 발생하면 push 파일 목록 누락과 실제 다중 원고 변경을 구분한다. 최신 direct-dispatch는 파일 목록이 없을 때 before..after 비교 API를 사용한다. 이미 반영된 보완을 다시 구현하거나 동일 원고를 재제출하지 않는다.
원장의 submitting은 최종 클릭 직전의 보존 기록이다. 해당 run의 SUBMIT_CLICKED와 성공 상태가 있으면 최종 제출 완료로 보고하되 공개 반영 확인과 구분한다. 공개 검증 미실시를 발행 실패로 해석하지 않는다. 자동 전달도 기존 제출 기록이 있으면 새 update run을 만들지 않고 해당 실행을 확인한다. 이로써 중복 러너 실행과 재수정 대기를 줄인다.
main에서 연속 push가 발생하면 content-standard-ci의 동일 ref 그룹이 앞 실행을 취소할 수 있다. cancelled는 검사 실패와 다르며, 중복 실행을 줄이는 기존 cancel-in-progress 설정을 무조건 해제하지 않는다.
1. 취소 run과 후속 run의 시작 시각·상태를 확인한다.
2. 성공한 후속 run의 커밋과 현재 main의 선택 원고 blob SHA를 비교한다. 검사 코드·설정의 관련 변경도 구분한다.
3. 같고 유효한 공통 회귀 검사 증거는 재사용한다. 후속 CI의 변경분 검사에 선택 원고가 포함되지 않았다면 그 원고 자체의 PASS라고 보고하지 않는다.
4. 발행이 승인돼 있으면 기존 start-direct-publish → update-posts 경로의 선택 원고 검증과 수정으로 이어간다. 전체 CI 재실행과 별도 검증 workflow를 끼워 넣지 않는다. 실제 기술 검증 실패는 해당 로그를 분석한 뒤 수정한다.
5. SUBMIT_CLICKED는 제출 클릭 증거다. 공개 검증 완료와 구분한다. 공개 검증 결과는 러너가 원장에 기록한다.

기존 신규 키워드 Ollama workflow도 제거한다. keywords.mjs CLI 역시 운영 중단 오류를 반환한다. 과거 생성 함수는 기록·fixture 호환을 위해 보존하되 운영 workflow에서 호출하지 않는다.

## 최신 확정 디자인 — 항목별 배치
이전 모든 목록의 3열 카드 변환을 대체한다. 소개는 문단, 영양은 표, 신체 변화는 구분선 목록, 궁합은 연한 녹색 영역의 조합별 설명, 주의사항은 경고 영역, 선택·보관은 체크리스트로 표시한다. PC와 모바일 모두 긴 설명은 본문 폭을 사용한다. 주제 번호는 23px·굵은 글씨로 표시한다. 렌더러의 스타일은 nh-direct-v2에 한정해 본문과 함께 전달하므로 스킨의 카드 CSS에 의존하지 않는다.
형광펜은 GPT가 핵심 수치, 성분 역할, 섭취 조건, 연구 적용 조건, 안전·보관 기준을 넓게 선택하여 source의 mark 태그에 저장한다. 렌더러는 의미를 추측해 강조하지 않고 저장된 강조를 보존한다. 글 내용이나 주제와 무관한 동일 키워드 목록을 자동 삽입하지 않는다.

## 본문 내부링크
작성 시 기존 게시글 목록에서 주제와 핵심 성분의 관련 글을 확인한다. 각 항목에서 관련 용어가 처음 설명되는 위치에 해당 기존 글을 연결한다. 요약문·하단 관련 글 링크만으로 본문 연결을 대신하지 않는다. 같은 항목의 반복 용어마다 링크를 붙이지 않으며, 존재를 확인한 주소만 사용한다. 링크는 본문 의미를 유지하는 a 태그로 저장하고, 공통 CSS가 청록색·밑줄·연한 배경·호버·키보드 포커스로 표시한다. 내용 검사나 재작성 루프는 추가하지 않는다.

직접 작성 제출 보호: direct-* 원고의 mark+strong 또는 mark+u+strong이 모두 없으면 기존 전달·선택 원고 검증에서 E_DIRECT_EMPHASIS_MISSING으로 차단한다. 이는 태그 통째 누락만 검출하며 의미·범위 검토를 대신하지 않는다. 별도 Actions 작업과 자동 재작성 루프는 추가하지 않는다.
신규 직접 작성 발행: posts/direct-*.json의 SP1 원고도 승인·대표사진·중첩 강조·HTML·이미지 검사를 거쳐 기존 publish-posts 경로를 사용한다. source_id를 지정하면 해당 신규 원고만 검사·발행한다. 성공 여부는 게시 URL과 원장·공개 반영 증거로 구분한다.
