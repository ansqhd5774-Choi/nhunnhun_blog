# 한입 건강 주장별 출처 품질 점검

대상은 한입 건강의 음식·영양소·약학·질병 글이다. 다른 사이트의 쿠폰 오류 수·코드 상태·계정 사용 검사를 건강 블로그의 결과로 가져오지 않는다. 링크가 열리는지와 건강 주장을 뒷받침하는지를 따로 확인한다.

## 점검 순서와 완료 기준

|순서|점검|완료 기준|
|---|---|---|
|1|공개 글·주장·출처 매핑|숫자 URL, 문제 문장/표 항목, 원문 URL을 연결한다. 글 끝 출처 목록만으로 모든 주장에 근거가 있다고 판정하지 않는다.|
|2|현재 중요한 주장부터 검토|새로 작성·변경한 수치, 섭취 기준, 효과, 약물·질병·안전 안내에 원문의 지지 범위를 확인한다.|
|3|접근 상태 분리|404/410, 서버 오류, 429, 인증·유료·자동 조회 제한, timeout, 미조회를 구분한다. HTTP 200에서도 오류 화면·차단 화면·무관한 내용·삭제된 내용을 확인한다.|
|4|동일 주장 근거 복구|이동 원문이나 최신 공식 자료를 먼저 찾고, 없으면 같은 대상·조건을 뒷받침하는 독립 자료를 확인한다. 홈페이지나 검색 결과로 대체하지 않는다.|
|5|유일한 근거가 사라진 주장 검토|접근 실패만으로 거짓이라고 단정하지 않는다. 다른 근거도 확인되지 않으면 해당 수치·효과·조건의 표현을 검토해 보류·삭제·범위 조정한다.|
|6|이력 보존|기존 인용정보, 교체 주소, 교체 이유와 실제 내용 확인 시점을 남긴다. 과거 기록을 새 확인으로 덮어쓰지 않는다.|
|7|수정 결과 확인|실제 수정이 필요한 글만 기존 update 경로를 사용한다. 원고 검토·저장·제출·공개 검증을 각각 기록한다.|

## 건강정보의 내용 확인

- 영양 수치: 식품·품종·제품, 생것/조리한 것/건조 상태, 가식부, 100g/1회분, 단위와 자료의 측정 기준을 대조한다. 다른 식품이나 조리 상태의 수치를 그대로 대체하지 않는다.
- 건강 효과: 연구 대상, 섭취·중재 조건, 비교군, 결과와 연구 유형을 확인한다. 성분의 역할·시험관 기전·관찰 결과를 해당 음식의 질병 예방·치료 효과로 확대하지 않는다.
- 섭취·약학·질병·안전 기준: 적용 국가, 대상 연령·집단, 제품·허가사항, 문서 버전·시행일을 확인한다. 현재 안내가 필요한 주장에 폐기된 지침이나 과거 보존본만 사용하지 않는다.
- 궁합: 영양 보완과 실제 흡수·상호작용 근거를 구분한다. 검토 결과는 확인된 장점 중심으로 반영하며, 모든 소개·효능·궁합 문장 뒤에 한계나 부정 문구를 반복 추가하지 않는다. 필요한 안전 경고는 유지한다.

## 접근·내용·발행 상태를 따로 기록

운영 기록에는 기존 `sourceId, publicUrl, claim, sourceUrl` 연결을 사용하고 필요할 때 다음 관찰을 덧붙인다. 원고 JSON에 새로운 필수 필드를 만들지 않는다.

- 접근: 확인 시점, HTTP 상태 또는 조회 제약, 최종 이동 URL, 실제 사용자 접근 관찰 여부.
- 내용: 지지함 / 일부 지지 / 충돌 / 미확인, 대상·조건, 검토자 또는 작업 식별자와 근거 위치.
- 이력: 원문 제목·발행 기관·게시일, 실제 내용 확인일, 적용일·개정일, 교체 이유, 이전 URL과 보존본 확보일. 모르는 값은 UNKNOWN/null로 둔다.
- 발행: 원고 저장, 실행 ID, 제출 상태, 공개 검증, 원장 상태. `PUBLIC_VERIFIED`는 공개 내용 반영 증거이며 의학적 감수 완료를 뜻하지 않는다.

보존본은 해당 시점의 인용 내용 확인용이다. 현재 섭취·약물·안전 기준의 유효성을 보존본만으로 확정하지 않는다. 원문을 확보했더라도 실제 해당 문장을 읽지 않았으면 내용 확인 완료로 기록하지 않는다.

## 오류 처리와 실행 범위

동일 도메인의 오류는 영향을 받는 글·주장을 묶어 관리한다. 대표 URL의 오류 유형을 확인하고 제한된 재조회·간격 조정 후 중단/재개 시점을 기록한다. 대표 URL이 성공했다고 같은 도메인의 모든 주장까지 확인 완료로 처리하지 않는다. 429·권한 제한·동일 timeout을 반복 호출하거나 접근 제한을 우회하지 않는다.

일반 Chat에 브라우저·CLI 사용을 필수로 요구하지 않는다. 현재 허용된 조회 도구에서 확인할 수 없는 항목은 미확인으로 기록하고 가능한 운영자/러너 확인 경로로 넘긴다. TinyFish 호출·연결·승인 요청은 계속 금지한다.

새로 작성·수정하는 핵심 주장은 기존 작성자 근거 검토에서 확인한다. 과거 출처의 일시 장애는 검토 후보로 남기며 전체 글 발행을 막지 않는다. 근거 공백이나 안전 오류는 영향을 받는 주장·글 범위에서 처리한다. 전체 과거 링크의 성공을 필수 CI 조건으로 만들거나 자동 의미 판정·재작성·새 발행 workflow를 추가하지 않는다.

## 운영 지표와 보고

근거 미확인인 현재 핵심 주장, 공개 글의 404/410 출처, 재검토 기한 초과, 단일 출처/도메인 의존을 관리한다. 글 수·주장 수·고유 URL 수를 구분하고 분모·확인 시점·미조회 범위를 표시한다. 링크 성공률만으로 콘텐츠 신뢰도나 검색 순위 변화를 단정하지 않는다.

이번 문서는 점검 기준의 적용이다. 실제 건강 글 전체의 출처 조사·복구·개정·공개 검증이 완료됐다는 의미가 아니다. 기존 32개 현황의 완료 수는 실제 항목별 검증이 끝난 경우에만 바꾼다.
